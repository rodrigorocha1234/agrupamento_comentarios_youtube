Plataforma Reutilizável de Clustering

Arquitetura orientada a contratos, configurada 100% via YAML, com suporte a Lakehouse RustFS/S3 (camadas Bronze, Silver e Gold), motores de processamento híbridos (Pandas e Polars), algoritmos de agrupamento não supervisionado (KMeans, DBSCAN, HDBSCAN), rastreamento de experimentos com MLflow, motor de regras de negócio seguro e API REST em FastAPI integrada ao Docker Compose.

Python 3.12+ Scikit-Learn & PyCaret Strategy Lakehouse RustFS / S3 100% Config-Driven (14 YAMLs) PLN Desativado por Padrão 75 Testes Automatizados
Fundamentos

1. Visão Geral da Arquitetura

A plataforma foi projetada para segmentar dados volumosos de avaliações de usuários (inicialmente da Steam API, mas desacoplada por contrato para suportar fontes como YouTube, Discord ou bancos SQL) sem necessidade de reescrita de código de domínio. Toda e qualquer diretriz de negócio, hiperparâmetro de Machine Learning ou seleção de variáveis é definida nos arquivos YAML contidos no diretório config/.

Isolamento por Contratos Strategy

Interfaces abstratas em app/contratos/ isolam o domínio contra fontes de dados, motores de clustering, repositórios lakehouse e sistemas de observabilidade.

Datalakehouse RustFS/S3 Zero Local

Nenhum dado é salvo em pastas locais do repositório. Toda a persistência é remota no RustFS S3, estruturada em camadas Bronze (bruto), Silver (limpo/tipado) e Gold (matriz analítica).

Expressões Seguras via AST Anti-Eval

Transformações e regras de negócio escritas em Pandas ou Polars são validadas por árvore sintática (AST) com whitelist de nós e escopo restrito, garantindo segurança contra execução de código arbitrário.

Configuração Declarativa

3. Instruções de Uso dos 14 Arquivos YAML

O sistema opera em modo Config-Driven: todo o comportamento analítico, tratamento de dados, hiperparâmetros de Machine Learning e limites de API são governados por arquivos YAML localizados em config/. O carregador unificado ConfYAML valida tipos, obrigatoriedades e regras arquiteturais em tempo de inicialização.

1. config/projeto.yaml Identificação & Flags Globais

Define a identificação do projeto, ambiente de execução e a ativação/desativação de módulos de alto nível. Atenção: Por regra arquitetural estrita, a funcionalidade pln.habilitado deve permanecer false.

ChaveTipoPadrãoDescrição
projeto.nomestrsteam_reviews_clusteringNome identificador do projeto.
projeto.ambientestrdesenvolvimentoAmbiente (desenvolvimento, staging, producao).
funcionalidades.pln.habilitadoboolfalseDesativa PLN por padrão para priorizar métricas comportamentais.
funcionalidades.api.habilitadobooltrueHabilita o serviço de API REST.
funcionalidades.mlflow.habilitadobooltrueHabilita o envio de métricas e parâmetros ao MLflow.

projeto:
  nome: "steam_reviews_clustering"

Configura o armazenamento remoto no RustFS/S3. Determina o bucket, prefixos das camadas Bronze, Silver e Gold, formatos de serialização (JSON para Bronze, Parquet para Silver e Gold) e particionamento diário.

config/datalake.yaml 
datalake:
  tipo: "rustfs" # rustfs | s3
  endpoint_url: "${S3_ENDPOINT_URL:-http://127.0.0.1:9000}"
  bucket: "${S3_BUCKET_NAME:-steam-reviews}"
  regiao: "${AWS_DEFAULT_REGION:-us-east-1}"

    prefixo: "bronze"
    formato: "json"
    particionar_por_data: true

    prefixo: "silver"
    formato: "parquet"
    particionar_por_data: true
  gold:
    prefixo: "gold"
    formato: "parquet"
    particionar_por_data: false

6. config/processamento.yaml Limpeza, Tipagem & Deduplicação

Rege a transformação da camada Bronze para Silver. Define deduplicação por chave primária, imputação de valores ausentes, conversão estrita de tipos e filtros de qualidade.

processamento:
  motor: "pandas" # pandas | polars
  deduplicacao:
    habilitado: true
    coluna_chave: "recommendamento_id"
    estrategia: "manter_ultimo"
  nulos:
    estrategia_padrao: "imputar" # imputar | remover | ignorar

        tipo: "float"
      - coluna: "voted_up"
        tipo: "bool"
7. config/preprocessamento.yaml Engenharia de Atributos & Escalonamento

Rege a transformação da camada Silver para Gold. Inclui tratamento de outliers (IQR ou Z-score), transformações matemáticas declarativas (ex: log1p, divisores de constantes) e escalonador normalizado (standard, minmax, robust).

config/preprocessamento.yaml 
preprocessamento:
  outliers:
    metodo: "iqr" # iqr | zscore | nenhum
    fator_iqr: 1.5
    acao: "truncar" # truncar | remover | manter
  transformacoes:
    - coluna: "author_playtime_forever"
      operacao: "log1p"
    - coluna: "votes_up"
      operacao: "log1p"
  escalonador:
    tipo: "standard" # standard | minmax | robust
    com_media: true
    com_desvio: true

10. config/regras_negocio.yaml Personas, Tags & Expressões Python

Permite cadastrar regras declarativas de negócio para atribuir rótulos semânticos (Personas) e alertas a clusters, ou marcar avaliações individuais. Suporta expressao_pandas e expressao_polars validadas por AST.

💡
Expressões Python Seguras: Você pode usar variáveis do dataframe como df['author_playtime_forever'] (Pandas) ou pl.col('author_playtime_forever') (Polars). O avaliador AST rejeita chamadas de sistema, imports ou atributos perigosos.
config/regras_negocio.yaml 
regras_negocio:
  habilitado: true
  motor: "pandas" # pandas | polars
  regras:
    - nome: "Veteranos Satisfeitos"
      descricao: "Agrupamento com alto tempo de jogo e forte recomendação positiva"
      habilitado: true
      alvo: "cluster"
      expressao_pandas: "(df['author_playtime_forever'] >= 120.0) & (df['taxa_recomendacao'] >= 0.70)"
      expressao_polars: "(pl.col('author_playtime_forever') >= 120.0) & (pl.col('taxa_recomendacao') >= 0.70)"
      acao:
        rotulo: "Veteranos Entusiastas"
        alerta: false
        prioridade: "baixa"

    - nome: "Críticos Influentes"
      descricao: "Agrupamento de avaliações negativas com alta repercussão de votos"
      habilitado: true
      alvo: "cluster"
      expressao_pandas: "(df['taxa_recomendacao'] <= 0.40) & (df['votes_up'] >= 3.0)"
      expressao_polars: "(pl.col('taxa_recomendacao') <= 0.40) & (pl.col('votes_up') >= 3.0)"
      acao:
        rotulo: "Críticos Relevantes"
        alerta: true
        prioridade: "alta"

    - nome: "Alerta Churn Veterano"
      descricao: "Avaliação individual negativa de jogador com mais de 500 horas de jogo"
      habilitado: true
      alvo: "amostra"
      expressao_pandas: "(df['author_playtime_forever'] >= 500.0) & (~df['voted_up'])"
      expressao_polars: "(pl.col('author_playtime_forever') >= 500.0) & (~pl.col('voted_up'))"
      acao:
        tag: "alerta_churn_veterano"
        alerta: true
        prioridade: "critica"

2. Gráfico de Dispersão 2D entre Atributos Reais (dispersao_2d) go.Scatter

Chave de ativação: config/analises.yaml -> analises.clusters.dispersao_2d: true
Mapeia a distribuição individual das avaliações no plano cartesiano construído a partir de duas features reais (por padrão, as duas primeiras colunas de config/atributos.yaml, ex: author_playtime_forever vs votes_up).

Objetivo Analítico:

  • Permitir ao analista enxergar a separação geométrica física entre os agrupamentos.
  • Inspecionar a densidade de amostras em regiões críticas (ex: alta repercussão de votos).
  • Validar visualmente a presença de avaliações atípicas e ruídos isolados.

Regras de Negócio Associadas:

  • Validação dos Limiares de Regra: Permite inspecionar se a fronteira de 120 horas de jogo e o volume de votos (3.0 votos médios) isolam perfeitamente o cluster de Críticos Relevantes no quadrante superior.
  • Detecção de Concentração: Revela se os jogadores de alta prioridade de alerta estão dispersos ou concentrados em um segmento específico.
3. Gráfico de Perfil Médio Multivariado dos Clusters (perfil) go.Bar (Grouped)

Chave de ativação: config/analises.yaml -> analises.clusters.perfil: true
Exibe barras agrupadas comparando lado a lado as médias de todas as variáveis de treino para cada cluster, incorporando o nome da Persona de Negócio diretamente na legenda (ex: Cluster 0 (Veteranos Entusiastas)).

Variáveis Contrastadas:

  • author_playtime_forever (Tempo total de jogo acumulado)
  • author_playtime_at_review (Tempo de jogo na data da postagem)
  • author_num_games_owned (Quantidade de jogos na conta Steam)
  • author_num_reviews (Total de avaliações já publicadas pelo autor)
  • votes_up (Votos de utilidade recebidos da comunidade)
  • votes_funny (Votos de humor recebidos)
  • comment_count (Número de comentários gerados na avaliação)

Regras de Negócio Associadas:

  • Justificativa da Persona: Oferece a explicação empírica do porquê o motor de regras classificou determinado grupo naquela persona.
  • Comparações Cruzadas: Mostra se grupos rotulados como Jogadores Casuais possuem também menor propensão a escrever outras avaliações (author_num_reviews).
  • Engajamento Social: Evidencia se os Críticos Relevantes geram mais discussões (comment_count) em virtude de sua insatisfação expressa.
4. Gráfico de Distribuição e Proporção de Clusters (distribuicao) go.Bar (Count & %)

Chave de ativação: config/analises.yaml -> analises.clusters.distribuicao: true
Apresenta a contagem absoluta de amostras em cada agrupamento, com rótulos percentuais diretos no topo das barras e codificação cromática com distinção explícita para amostras de ruído (#e74c3c para Ruído -1 e #3498db para clusters válidos).

📈
Regras de Negócio Associadas & Dimensionamento de Impacto:

Quando uma regra de negócio como "Críticos Influentes" dispara um alerta de prioridade alta, este gráfico permite à liderança de produto quantificar imediatamente a magnitude do risco:

  • Risco Sistêmico: Se o cluster sob alerta representa mais de 25% da base de avaliações, o jogo enfrenta rejeição ampla que exige correção imediata em patches.
  • Nicho Específico: Se representa menos de 3%, trata-se de um subgrupo especializado (ex: jogadores com hardware antigo ou preferências muito específicas).
  • Controle de Qualidade do Algoritmo: Alerta os cientistas de dados se a taxa de ruído (-1) do DBSCAN/HDBSCAN ultrapassar 20%, recomendando ajustes em min_samples ou eps em config/clustering.yaml.
5. Projeção Exploratória PCA 2D (pca_2d) go.Scatter (PCA)

Chave de ativação: config/analises.yaml -> analises.clusters.pca_2d: false
Reduz linearmente a matriz multidimensional de treino para as duas primeiras componentes principais (PC1 e PC2).

Regras de Negócio Associadas: Permite inspecionar a sobreposição global entre as personas sem perda arbitrária de atributos. Contém disclaimer obrigatório alertando que a projeção 2D é meramente exploratória e não preserva 100% da variância original.

Chave de ativação: config/analises.yaml -> analises.clusters.boxplot: false
Compara quartis (Q1, Mediana, Q3), valores atípicos e média de uma variável escolhida entre os clusters.

Regras de Negócio Associadas: Suporta a auditoria da regra de amostra "Alerta Churn Veterano" (author_playtime_forever >= 500h & ~voted_up), revelando o grau de dispersão da cauda longa de tempo de jogo e a assimetria da distribuição antes da aplicação do escalonador.

Execução

5. Operação e Guia de Comandos (executar.sh)

O script utilitário ./executar.sh encapsula todas as tarefas operacionais do repositório, garantindo o carregamento correto de variáveis de ambiente e ativação do ambiente virtual.

ComandoAçãoExemplo de Uso
./executar.sh test Executa ruff (linter/format), pytest (testes unitários) e checagem de tipos estrita (pyright). ./executar.sh test
./executar.sh pipeline [ID] Executa o ciclo analítico completo para um ID de jogo (lendo do Lakehouse S3). ./executar.sh pipeline 730
./executar.sh pipeline [ID] --coletar Extrai dados novos da API externa antes de rodar o pipeline analítico. ./executar.sh pipeline 730 --coletar
./executar.sh api [--docker] Inicia a API REST FastAPI localmente ou em contêiner Docker Compose. ./executar.sh api --docker
./executar.sh infra Sobe contêineres de suporte (RustFS S3, PostgreSQL, MLflow, Prometheus, Grafana). ./executar.sh infra
./executar.sh infra-down Encerra todos os contêineres de suporte. ./executar.sh infra-down

Hot-reload de Configurações:

O contêiner api-fastapi monta o volume ./config:/app/config:ro. Qualquer modificação feita nos arquivos YAML é refletida imediatamente nas novas predições e requisições sem necessidade de reconstruir a imagem Docker.
