01 Visão Geral e Invariantes Arquiteturais

O Steam Reviews Clustering é uma plataforma analítica de engenharia de dados e machine learning não-supervisionado desenhada para segmentar o perfil comportamental de jogadores na Steam a partir de metadados de telemetria de consumo, engajamento e votos de recomendação.

🛡️
Preservação Textual sem PLN
As avaliações textuais são preservadas integralmente para auditoria humana. É estritamente proibido o uso de PLN, LLMs, embeddings ou análise de sentimento no algoritmo de clustering.
🔒
Tipagem Estrita e GoF
Projetado sob tipagem estrita com pyright --strict e 0 instâncias de Any. Módulos com exatamente duas palavras e padrões GoF com proibição de if/elif para tecnologia.
⚙️
Configuração Declarativa
Gerenciamento exclusivo via ConfYAML com schemas Pydantic (extra="forbid"), cálculo de SHA-256 e sem execução arbitrária via eval/exec.
🏛️
Arquitetura Medalhão Lakehouse
Partição Bronze (JSON bruto particionado), Silver (Parquet deduplicado e validado) e Gold (dimensões agregadas, perfis de cluster e métricas estatísticas).
⚠️ Regra Semântica Crítica de Dados

O idioma brazilian registrado pela Steam API indica apenas a preferência de idioma da interface/avaliação do usuário e nunca comprova residência física no Brasil. O sistema proíbe categoricamente qualquer inferência geográfica baseada nesse atributo.

📐 Semântica das Multiplicidades e Tipos de Relacionamento UML

Na Modelagem UML (Unified Modeling Language), a multiplicidade define a cardinalidade numérica estrita — isto é, a quantidade mínima e máxima de instâncias válidas de uma classe que podem se relacionar com uma única instância da classe oposta. No projeto Steam Reviews Clustering v4.1, a definição de multiplicidades explícitas em todas as conexões garante previsibilidade de ciclo de vida, ausência de referências nulas não controladas e conformidade integral com os padrões de projeto do GoF.

Multiplicidade "1" (1..1)
Exatamente Uma Instância Obrigatória. A classe dependente não pode operar sem a instância parceira e a referência jamais pode ser nula (None). No Python 3.12, isso é imposto via tipagem estrita no construtor sem valor padrão opcional.
Multiplicidade "1..*"
Uma ou Mais Instâncias (Coleção Não Vazia). Representa conjuntos ou fábricas polimórficas que gerenciam múltiplos adaptadores. Exemplo: a FabricaAgrupadores instancia 1 ou múltiplos estimadores polimórficos.
Composição ("*--")
Vínculo Forte de Ciclo de Vida. A parte pertence unicamente ao todo e é instanciada e destruída junto com a classe hospedeira. Exemplo: OrquestradorPrincipal compõe suas instâncias de coordenação.
Agregação ("o--")
Acoplamento Fraco (Injeção de Dependência). A parte existe independentemente e é injetada para promover desacoplamento e testabilidade via mocks. Exemplo: Repositórios e UoW injetados no executor.

💡 Como o Python 3.12 Garante essas Multiplicidades

No projeto, as multiplicidades "1" (obrigatórias) são rigidamente asseguradas pelo type checker Pyright Strict: nenhum construtor aceita parâmetros com valor None a menos que o tipo seja explicitamente declarado como T | None. Relações "1..*" são garantidas através de coleções tipadas como Sequence[T] validadas contra listas vazias via verificações de pré-condição (if not colecao: raise ValueError(...)), prevenindo estados nulos e inconsistências de domínio em tempo de execução.

4.3. Governança Declarativa e Validação Estrita com Pydantic v2

No Steam Reviews Clustering v4.1, o Pydantic v2 atua como a espinha dorsal de governança, conformidade de esquemas e segurança de tipos em todas as fronteiras de entrada e saída (I/O Boundaries) do sistema. Seguindo o princípio funcional "Parse, Don't Validate", nenhuma estrutura de dados externa (arquivos YAML, variáveis de ambiente ou payloads HTTP) transita no domínio sem antes ser analisada, validada e convertida em modelos imutáveis de alta integridade.

🛡️
extra="forbid" (Fail-Fast)
Qualquer chave não mapeada ou desconhecida nos arquivos YAML ou requisições HTTP dispara um ValidationError imediato na inicialização. Erros de digitação nunca passam despercebidos.
🔒
frozen=True (Imutabilidade)
As instâncias de configuração são congeladas e somente-leitura por design. Nenhum componente ou thread do pipeline pode modificar estados de configuração em tempo de execução.
🚫
Sem eval / exec Dinâmico
É terminantemente proibida a execução de expressões Python arbitrárias a partir dos YAMLs. O parsing é estritamente tipado e desacoplado de injeções de código.

Matriz de Responsabilidade: Pydantic v2 vs Python Dataclasses

Para conciliar máxima segurança nas bordas com altíssimo desempenho computacional no processamento em memória, a arquitetura divide claramente as funções:

Camada / Domínio Tecnologia Utilizada Configuração Aplicada Finalidade & Racional Arquitetural
Bordas de Configuração YAML Pydantic v2 (BaseModel) extra="forbid", frozen=True Validação estrita em tempo de carga dos arquivos em configuracoes/ pela fachada ConfYAML.
Bordas de API REST (DTOs) Pydantic v2 (BaseModel) extra="forbid" Contratos de requisição e resposta do FastAPI, serialização JSON e geração do Swagger/OpenAPI.
Entidades de Domínio Interno Python Standard Library (@dataclass) frozen=True, slots=True Representação em memória de alta performance para ReviewSteam, AutorSteam e PaginaReviews (zero overhead de validação em loops).

1. Padrão Base de Configuração Imutável (app/configuracao_geral/modelos_configuracao.py)

Todos os modelos de configuração herdam de ModeloBaseConfiguracao, assegurando a política uniforme de rejeição de campos extras e imutabilidade estrutural:

python — Modelos Pydantic v2 de Configuração com ConfigDict 
from pydantic import BaseModel, ConfigDict

4.10. Troubleshooting e Resolução de Problemas Frequentes

Sintoma / Erro Causa Provável Procedimento de Correção
HTTP 429 da Steam API Taxa de requisições excedeu o limite da Steam. O ControladorResiliencia aplica backoff exponencial automaticamente. Ajuste taxa_maxima_requisicoes_minuto em steam_api.yaml se persistir.
Erro de Conexão no PostgreSQL (5432) Container do banco de dados ainda não está pronto para conexões. Execute docker compose logs postgres e verifique se o socket está pronto. O sistema possui fallback transparente para SQLite staging se necessário.
Pyright: Argument of type "dict" cannot be assigned... Invariância de tipos genéricos em coleções Pydantic ou dicionários. Utilize Mapping[str, ...] em vez de dict[str, ...] nas assinaturas onde houver covariância de tipos primitivos.
Silhueta Retornando Ruído (-1.0) Algoritmos baseados em densidade (DBSCAN/HDBSCAN) marcaram pontos como ruído. Comportamento esperado: o AvaliadorObjetivo calcula a silhueta exclusivamente nos pontos não-ruído e aplica penalização proporcional no score composto.
