# Regras Python e arquitetura
- Python >=3.12; tipagem explícita, checker em modo strict; proibido `Any`, `typing.Any`, `from typing import *` e alternativas disfarçadas.
- Nomes de classes, métodos, atributos, exceções e módulos próprios em português.
- Módulos/pacotes Python próprios: **exatamente duas palavras separadas por `_`**, salvo `__init__.py`, `__main__.py`, `conftest.py` e exigências externas.
- Uma classe principal por arquivo, SOLID, encapsulamento proporcional; composição antes de herança; associação/agregação/composição UML explícitas.
- `Protocol`, `Generic` e `TypeVar` para serviços genéricos quando necessário; `@override`, `@final`, `ABC` e `@abstractmethod` com justificativa semântica.
- Strategy/Factory/Adapter/Observer/Repository/Facade quando resolverem extensão real; preferir políticas a ifs extensos.
- Priorizar padrão Python nativo -> stdlib -> vetorização -> abstração própria. `zip(strict=True)` quando comprimentos devem coincidir.
- Proibido pandas `iterrows`, `itertuples` e `apply(axis=1)` quando há operação vetorizada; loops sobre modelos/folds/configurações são válidos.
- Exceções de domínio em português e encadeamento `raise ... from erro`. Não engolir erros.
- `pytest`: unitários, integração, contratos e testes parametrizados. Segredos exclusivamente por variáveis de ambiente.
- Configurações variáveis em YAML, sem hardcoded de nomes de colunas, thresholds, modelos, paths ou parâmetros.
